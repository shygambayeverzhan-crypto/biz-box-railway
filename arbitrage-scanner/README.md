# Арбитражный сканер для Telegram — MVP

Бот получает публичные spot-снимки стакана, сравнивает пары к USDT и отправляет оценку подписчикам, которые включили её командой `/start`. Токены Telegram — секрет владельца; ключи бирж и торговые разрешения не используются. Ордеров и вывода средств в коде нет.

> Источники котировок в этой версии — **Bybit Kazakhstan** и **Binance Global public market-data API**. Это не подтверждает, что Binance Global стакан совпадает с продуктом Binance Kazakhstan. Не используйте такие сигналы как готовые инструкции для сделок на Binance Kazakhstan; сначала подтвердите совместимость локального рынка и API.

## Что реализовано

- `/start`, `/help`, `/settings`, `/status`, `/stop`; подписка хранится в SQLite, `/stop` физически удаляет Telegram ID.
- Команды пользователя ограничены по частоте; рассылка только личным подписчикам; `/stop` повторно проверяется перед доставкой пакета.
- На старте бот проверяет наличие одинакового spot-инструмента со статусом Trading на обоих источниках и сопоставляет base/quote. Неактивные/несовпадающие символы пропускаются.
- Bybit V5 API использует региональный хост `api.bybit.kz`; Binance использует документированный домен публичных market-data endpoints `data-api.binance.vision`.
- Сканируются только настроенные пары к USDT и только спотовые стаканы.
- Считается оба направления: купить по asks одного источника, продать по bids второго. Средневзвешенные цены учитывают загруженную глубину и заданный лимит суммы.
- Taker-комиссии задаются отдельно в `.env` и явно помечаются как оценки.
- Фильтруются старые/рассинхронизированные снимки и слабая ликвидность; повторы по паре/направлению подавляются cooldown.
- Таймауты, до трёх попыток с экспоненциальной задержкой и jitter, обработка HTTP 429/Retry-After, circuit breaker при серии сетевых сбоев.
- Очередь из одного пакета коалесцирует ожидающие сигналы в пользу более свежих данных. Рассылка ограничена 20 сообщениями/с глобально и не чаще одного сообщения в секунду одному пользователю; просроченные пакеты не продолжают рассылаться.
- SQLite работает с WAL; Docker Compose сохраняет базу в отдельном volume.

## Требования

- Python 3.12+ для локального запуска или Docker Engine + Docker Compose.
- Telegram bot token, который создаётся через официального `@BotFather`. Настоящий token нельзя коммитить или отправлять в чат.
- Сетевой доступ из места запуска к Telegram Bot API, `api.bybit.kz` и `data-api.binance.vision`.

## Локальный запуск на Windows PowerShell

Из каталога проекта выполните:

```powershell
.\setup.ps1
notepad .env
```

В `.env` заполните `BOT_TOKEN` токеном от `@BotFather`, сохраните файл и запустите:

```powershell
.\start.ps1
```

`setup.ps1` создаёт виртуальное окружение, устанавливает зависимости и копирует `.env.example` в `.env`. Если Python Launcher (`py`) отсутствует, установите CPython 3.12 с официальной страницы и откройте новое окно PowerShell. Без скриптов те же шаги: `py -3.12 -m venv .venv`, `.\.venv\Scripts\python.exe -m pip install -e .`, затем `.\.venv\Scripts\python.exe -m arbscanner`.

Для Linux/macOS создайте окружение `python3.12 -m venv .venv`, активируйте `source .venv/bin/activate`, затем выполните `pip install -e .` и `python -m arbscanner`.

Оставьте процесс работающим. Откройте личный чат с ботом, отправьте `/start`; `/status` показывает проверенные общие рынки, ошибки источников, очередь и статистику доставки. `/stop` удаляет подписку. Polling не требует публичного адреса или настройки webhook.

## Docker / VPS

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`.
2. Выполните `docker compose up -d --build`.
3. Смотрите журнал: `docker compose logs -f scanner`.
4. Обновление кода: `docker compose up -d --build`.

Volume `scanner-data` сохраняет SQLite при пересоздании контейнера. Не размещайте `.env` в Git. Настройте резервную копию базы и мониторинг логов самостоятельно.

На VPS бот использует polling и не требует открытого входящего порта. Для бесплатного 24/7 размещения можно изучить OCI Always Free; провайдер предупреждает, что регистрация обычно требует банковскую карту, ресурсы создаются в домашнем регионе, а простаивающие инстансы могут быть отозваны. Проверьте отметку Always Free в консоли и не создавайте платные ресурсы. Если карты/аккаунта нет, бесплатный вариант — локально на компьютере, который остаётся включённым. Бесплатный web-хостинг, засыпающий при простое, не обеспечивает непрерывное сканирование.

## Настройки `.env`

- `SYMBOLS`: список формата `BTCUSDT,ETHUSDT`; код автоматически оставит только активные общие рынки.
- `SCAN_INTERVAL_SECONDS`: интервал прохода (1–60 секунд; стартовое значение 5).
- `ORDERBOOK_DEPTH`: глубина стакана, 1–50 уровней.
- `MIN_NOTIONAL_USDT`: минимальная сумма расчёта, ниже которой не формируется сигнал.
- `MAX_NOTIONAL_USDT`: верхняя граница суммы расчёта.
- `MIN_NET_SPREAD_PERCENT`: порог после комиссий.
- `MAX_QUOTE_AGE_SECONDS`, `MAX_CROSS_EXCHANGE_SKEW_SECONDS`: фильтры свежести снимков.
- `MAX_SIGNAL_AGE_SECONDS`: сколько секунд пакет уведомлений считается актуальным в очереди.
- `BYBIT_TAKER_FEE_PERCENT`, `BINANCE_TAKER_FEE_PERCENT`: оценочные ставки, в процентных пунктах; `0.10` означает 0.10%.
- `COOLDOWN_SECONDS`: пауза повторного сигнала по одной паре и направлению.
- `BYBIT_BASE_URL`, `BINANCE_BASE_URL`: официальные публичные REST-хосты, которые можно переопределить.
- `DATABASE_PATH`: путь к SQLite.

## Как считается разница

Для заданного объёма `q` бот проходит asks биржи покупки и bids биржи продажи, считает фактический quote-оборот в доступной глубине и получает VWAP. Максимальное количество ограничивается доступной глубиной и `MAX_NOTIONAL_USDT`; если расчётный объём меньше `MIN_NOTIONAL_USDT`, связка отбрасывается.

Оценка чистого процента:

`(sell_quote × (1 − sell_fee) − buy_quote × (1 + buy_fee)) / (buy_quote × (1 + buy_fee)) × 100%`

В формуле комиссии заданы долями от quote-суммы. Это упрощение: точное списание и ставка зависят от тарифа и биржи. Индивидуальная комиссия пользователя не запрашивается.

## Ограничения и риски расчёта

- Binance endpoint — глобальный публичный market-data API. Binance Kazakhstan имеет локальный продукт, но доступные документы не подтверждают, что глобальный стакан, листинги и доступность совпадают с локальным продуктом. В уведомлении источник подписан как Binance Global.
- Bybit API хост локализован для Казахстана, но доступность конкретного аккаунта/инструмента следует проверять в актуальных условиях самой платформы.
- REST-стакан является снимком. Binance REST depth не возвращает timestamp стакана; для него используется время получения ответа, поэтому максимальный возраст/рассинхрон не являются гарантией синхронного источника. Для более частых и точных сигналов потребуется переход на WebSocket и сбор локальной книги.
- Не проверяются ввод/вывод, сети, сетевые комиссии, переводы между биржами, баланс пользователя, лимиты ордеров и фактическое исполнение. Арбитраж чаще требует заранее размещённых балансов на обеих площадках.
- Не используются KZT-пары, futures, perpetual, margin или DEX. Налоги и юридические требования не оцениваются.
- Рассылка — личными сообщениями с pacing до 20 сообщений/сек глобально и не чаще 1 сообщения/сек на пользователя. При сроке актуальности 20 секунд теоретический предел — около 400 получателей на пакет без сетевых ошибок; фактическая ёмкость ниже. Просроченные получатели пропускаются, это видно в `/status`. Для большой публичной аудитории используйте Telegram-канал как fan-out либо отдельную масштабируемую очередь.
- Порог и комиссии — настройки владельца, не прогноз дохода и не инвестиционная рекомендация.

## Что нужно владельцу до публичного продвижения

1. Создать бота у `@BotFather`, заполнить `BOT_TOKEN` локально и не показывать его другим.
2. Проверить у поддержки/API Binance Kazakhstan, какой официальный публичный market-data endpoint и список spot-рынков применимы к локальному продукту. Не объявлять глобальные котировки ценами локальной Binance KZ.
3. Сверить `SYMBOLS` и комиссии с текущими рынками/условиями обеих площадок.
4. Запустить локально и убедиться, что `/status` показывает общие активные рынки. Если список пустой, не снижать фильтры вслепую — выяснить источник или символ.
5. Для 24/7 получить хостинг-аккаунт; бесплатный облачный уровень может требовать карту и не гарантирует наличие VM.
6. Проверить поведение доставки на тестовом пользовательском аккаунте, затем решить, подходит ли DM-рассылка целевой аудитории.

В проекте нет реальных токенов, ключей бирж, ордерной логики или автоматически создаваемого облачного ресурса.
